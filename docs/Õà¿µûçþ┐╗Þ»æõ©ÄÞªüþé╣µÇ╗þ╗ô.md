## 1 引言

在本实验中，学生需要实现一个**多周期 RV32I 处理器**。它应当能够执行与之前已经实现的**单周期版本**相同的一组指令。

单周期处理器的含义是：一条指令的所有执行阶段，例如取指、译码等，都必须在一个时钟周期内完成。这会带来以下问题：

- 需要分开的指令存储器和数据存储器。
- 同样地，需要三个加法器：两个用于 PC 更新，一个用于 ALU。可是加法器在硬件面积方面比较昂贵。
- 时钟周期必须足够长，以容纳数据通路最长的指令，也就是 `LW`。但是对于数据通路较短的其他指令，其实并不需要这么长的时间。

如图 1 所示，多周期执行是构造处理器的另一种方式。它可以把一条指令的执行过程拆分到多个不同的周期中，从而避免上述问题。具体来说，体系结构状态单元（Memory、Register File、ALU）会被非体系结构状态单元（寄存器）分隔开。

这样做之后，一个存储器就足够了，因为取指和数据访问可以在不同的周期中完成；一个加法器也可以复用，因为 PC 更新、Branch/Jump 目标地址计算以及算术逻辑运算会在不同的周期中完成。此外，一条指令所需的周期数会与它的复杂度或数据通路长度相关。

## 2 设计与实现指导

多周期处理器设计的关键在于：

1. 控制器设计；
2. 在系统中插入寄存器后进行整体结构重建。

### 2.1 控制器设计

控制器主要由三个部分组成：

1. 原来的组合逻辑一级译码器被一个**有限状态机 FSM** 替代；
2. 二级 ALU Decoder 保持不变；
3. Sign Extender 的选择信号是由 `op` 决定的组合逻辑函数。

图 2 展示了多周期 RISC-V 控制器的结构：FSM、ALU Decoder 和 Instruction Decoder 共同生成控制信号。

图 3 给出了 FSM 的起点。结合系统图，下面用最长指令 `LW` 简要说明多周期处理器如何执行：

- **阶段 1**：`PC_reg` 输出 Memory 地址端口，对应的指令被加载到 `instr_reg`。
- **阶段 2**：`instr_reg` 的输出被译码。`LW` 的基地址存放在 `rs1` 中，并被写入 `rd1_reg`；地址偏移量由 Sign Extender 生成。
- **阶段 3**：基地址和偏移量进入 ALU 做加法，结果写入 `alu_reg`。
- **阶段 4**：选择 `alu_reg` 的输出作为结果，并送入 Memory 的地址端口读取数据。读出的数据存入 `data_reg`。
- **阶段 5**：选择 `data_reg` 的输出作为结果，并写回寄存器堆。

可以注意到，上述流程中没有执行 `PC = PC + 4`。ALU 只在阶段 3 被用于 `LW` 的地址计算，这意味着它在其他阶段可以用来计算下一条指令地址。由于 PC 更新是大多数指令都需要的操作，而且最好尽早完成，所以阶段 1 是 ALU 空闲且适合做 `PC+4` 的第一个阶段。

为了完成控制器设计，需要做到：

- 在实现之前先完成 FSM：填入缺失的状态输出；添加状态转移条件；添加或修改状态以支持 `LUI`。
- 为了保证可维护性和可读性，将 FSM、ALU Decoder 和 Instruction Decoder 分别实现为独立模块，然后在 Controller 中组装。
- 思考你要使用 Mealy FSM 还是 Moore FSM，为什么？你会如何在 RTL 中编码控制 FSM？使用 one-hot、二进制编码，还是枚举类型？这些选择在面积、时序和调试便利性之间有什么取舍？
- FSM 的状态输出应当有默认值。

图 3 给出的 FSM 起点包含以下状态：

- `S0 fetch`：取指阶段，选择 PC 作为 Memory 地址，写入 IR，ALU 做 `PC+4`，更新 PC。
- `S1 decode`：译码阶段。
- `S2 exe_addr`：地址计算阶段，通常用于 `LW/SW`。
- `S3 mem_rd`：读取数据存储器。
- `S4 wb_mem`：把 Memory 读出的数据写回寄存器堆。
- `S5 mem_wr`：写数据存储器。
- `S6 exe_r`：执行 R-type ALU 运算。
- `S7 wb_alu`：写回 ALU 结果。
- `S8 beq`：执行分支比较和分支控制。
- `S9 exe_i`：执行 I-type ALU 运算。
- `S10 jal`：执行 JAL 跳转，并更新 PC。

其中多个状态的控制信号在图里是空白的，需要学生自行补全。

### 2.2 系统集成

需要补全图 1 中的系统架构。原图可能还不支持 `BEQ` 和 `LUI`。

需要思考：

- `BEQ` 和 `JAL` 除了 `PC=PC+4` 以外，还需要额外的地址计算。考虑到 ALU 在阶段 1 和阶段 3 已经被使用，哪个阶段适合进行这类地址计算？
- 可能需要更多寄存器；某些多路选择器也可能需要替换成输入更多的多路选择器。

### 4.1 多周期架构

需要回答：

- 在图 1 中，有些寄存器带写使能 `en`，有些没有。解释为什么有的需要 `en`，有的不需要。

- 简要描述你遇到过的 bug。

### 4.2 性能分析

平均 CPI 是每类指令 CPI 与该类指令出现比例的加权和。

从图 3 可以看出，不同指令可能需要不同数量的周期。对于你用于验证的程序，需要回答：

- 根据手动计算，总共需要多少周期？
- 从仿真和波形中统计，总共是多少周期？
- 二者是否完全相同？
- 计算你的程序 CPI。

报告中应基于你的测试程序或 benchmark 提供表格，并计算最终平均 CPI。

# 最后要点总结

1. 这次不是单周期，而是要做**多周期 RV32I 处理器**。
2. 重点是补全并实现 **FSM 控制器**，把 FSM、ALU Decoder、Instruction Decoder 分模块写清楚。
3. `LW` 最长，大概经过：Fetch → Decode → 地址计算 → Memory read → Write back。
4. 需要支持与 RISC-V-1 相同的指令集，并额外注意 `BEQ`、`JAL`、`LUI` 的数据通路。
5. 报告必须包含：系统图、FSM 图、第 4 节问题答案、CPI 分析、复用模块说明、测试汇编程序、验证结果。
6. 代码除 testbench 外必须可综合；memory 初始化不要写在 memory 模块里，要在 testbench 里用 `$readmemh` 层级加载。
7. 评分脚本可能卡模块名、端口名、实例名、数组名，所以你需要和 RISC-V-1 模板保持一致。
8. 最迟考核时间是 2026 年 6 月 30 日周二 10:15–12:00。
